## 16:20:21 +1000 — Fix guest-side duel crash, hotspot screen scrolling

- **Prompt author:** Mobark Bacran
- **Request:** The challenge screen is hard to scroll when creating a hotspot;
  what is the hotspot even for; and the player who receives the invite crashes
  when they lock their position, just before the countdown.
- **Work completed:**
  - **Crash (root cause, my own regression):** `ConnectingScreen.onConnected`
    made `App.tsx` swap the screen out for the duel, which unmounted
    `ConnectingScreen` → `useDuelSession`'s cleanup ran
    `connection.disconnect()` → `rtcChannel.close()`. The duel then held an
    already-closed DataChannel, so the first `channel.send({type:"ready"})`
    on locking position threw "The local duel connection is not open" and
    red-screened. Guest-only, because only the guest's channel lifetime was
    owned by a screen that unmounts.
    Fixed with an ownership handoff: `useDuelSession` gained `handOff()`
    (mirroring the `hotspotHandedOff` ref pattern already in
    `QrDisplayScreen`), which `ConnectingScreen` calls before notifying the
    caller, so unmount no longer closes a channel the duel now owns. Added
    `useDuelSession.test.ts` covering both directions, and verified it fails
    with the fix reverted.
  - **Crash resilience in `PreRound`:** the `buzz`/`countdown` sends run
    inside `setTimeout`, where a throw is an unhandled crash rather than a
    catchable error — so any real mid-round drop red-screened too. Routed all
    sends through a `safeSend` that surfaces "Lost the connection to your
    opponent." instead, and tracked the countdown timers so unmounting
    mid-countdown clears them rather than firing on a dead channel.
  - **Silently dropped calibration messages:** `isDuelMessage` in
    `duelDataChannel.ts` validated against a stale copy of the `DuelMessage`
    union — missing `clockPing`/`clockPong`, so the clock-offset calibration
    (#48, already merged) was being discarded over real WebRTC, quietly
    breaking reaction-timing fairness. Added both cases.
  - **Host-server thrash:** `onHostConnected`/`onConnected` were inline
    arrows, and `QrDisplayScreen` keys its host-server effect on that prop —
    so any `App` re-render would tear the signaling server down and restart
    it, dropping a guest mid-join. Replaced both with one `useCallback`.
  - **UI:** `QrDisplayScreen` was a fixed `View`; in iOS hotspot mode the
    instructions card plus two text inputs plus the 310px-min QR card
    overflowed with no way to scroll, and the keyboard covered the inputs.
    Wrapped in `KeyboardAvoidingView` + `ScrollView`
    (`keyboardShouldPersistTaps="handled"`), moved padding/gap to the scroll
    content. Also rewrote the hotspot subtitle to actually explain the mode's
    purpose ("No shared Wi-Fi? Your phone becomes the network…") since
    nothing in the UI said what it was for.
